## 三、🔴 致命问题（4个，优先修）

### 1. scale bug — 编译器生成SCL语义错误（最严重）

**现象**：`backend_s7.py` 的 `_emit_add` 不乘 scale_base/scale_spline，但训练后这两个参数严重偏离1.0：
```
kan_layers.0.scale_base: 1.7088   (+70.9%)
kan_layers.0.scale_spline: 1.4052 (+40.5%)
kan_layers.1.scale_base: 1.6979   (+69.8%)
kan_layers.1.scale_spline: 1.2174 (+21.7%)
```

**实测后果**（亲自跑对比实验）：
```
PyTorch vs 无scale模拟SCL：
  logit MAE:  4.02
  logit MaxAE: 13.97   ← 论文声称DA bound 0.079（177倍超界）
  分类一致性: 83.0%    ← 论文声称99.93%
```

**为什么验证链没发现**：DA bound（affine_verify.py L322-323）用带scale权重算✅；E6验证（evaluate.py L772 `_sb * base_w + _ss * spline_t`）用带scale模拟✅；TIA 0e0w只验语法✅。四套证据各自自洽，但**真实SCL是唯一落地产物，它错了**。

**根因**：backend重构时丢了旧模板（scl_templates.py L152）里的scale乘法。

**修复方案（推荐B）**：
- 方案B：frontend `kan_to_ir` 折叠scale进权重——`base_matmul` W改为 `base_weight * scale_base`，BsplineLUT table改为 `table * scale_spline`
- 修复后：重新生成全部SCL（results/scl_output/ 24个文件都是错的）+ 重跑E6/E50确认"100%一致"在新SCL上成立

**涉及文件**：`code/neuroplc/frontend.py`（改）、`code/neuroplc/backend_s7.py`（不改）、`results/scl_output/*.scl`（重新生成）
